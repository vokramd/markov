## Findings and limits

Both updater runs reported **“Omarchy shell did not become ready after restart.”**, then continued tool checks and returned 0. This was a serial-console test with no logged-in graphical desktop. Package transactions, repository persistence, reboot, CLI and native recovery are verified; graphical shell readiness and interactive desktop UX are not. Do not hide this warning or claim desktop-wide QA.

The initial ISO seed's optional keyboard-layout override was rejected by the installer; leaving the optional input-method layout empty (the ISO validator's supported value) fixed it. Initial serial harness attempts inherited root runtime paths; a proper guest login environment resolved that before updates. Native recovery needs an interactive `r/l/c` menu; piped yes/no input was rejected, and the test was retried interactively. These are local harness/installer findings, not Markov defects or host changes.

Fixtures use current engine code with 0.1.0/0.1.1 version overrides, not historical tagged-source checkpoint migration. Final new payload is the existing `b1cfa43` candidate. No firmware/Secure Boot, hardware diversity, GUI, GPU or native Arm coverage is claimed. Eleven container rows and signature/hash negatives remain separate evidence in [pilot results](cc-71-pilot-results.json).

No DreamHost writes, deploy keys, m720q access, real-key signing/copy/backup, host package installs, Git pushes/tags/PRs, Releases or GHCR publication. The VM approval authorized only this local VM. Production still needs staging/confinement approval and testing, encrypted real-key backup/restore, approved release signing, native Arm CI and clean-tag release review.

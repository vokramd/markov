# Codify and ops steps carry Markov's case

Markov is no longer alone. As of November 2026, at least three products already deliver its headline pitch, "YAML workflows that chain headless Claude Code and Codex with deterministic steps": **Archon** (an MIT YAML DAG engine with about 23.9k stars and weekly releases), **Claude Code dynamic workflows** (first-party, written by Claude for you), and **GitHub Agentic Workflows** (v1.0.1, multi-engine, budgets on by default). Agent frameworks from Google, Microsoft and LangChain now all sell "deterministic workflow with agent nodes" as their main feature. So "mix agents with deterministic steps", "durable resume", "JSON-schema answers", "scheduling" and "vendor neutrality" are table stakes, and Markov should stop leading with them. Five claims survived every comparison in this research. The first and most distinctive is `markov codify`: an incremental, replay-validated loop that moves no-judgment agent work into native steps. No product or paper found combines its parts. The second is kill-on-breach limits on turns, tokens, duration and dollars, applied the same way to both Claude Code and Codex. The third is native infrastructure steps (k8s_job, ansible, paginated HTTP, sandboxes) plus markovd on Kubernetes. The fourth is rule-engine gates. The fifth is a step debugger with breakpoints. Markov's honest answer to most "why not X?" questions is therefore narrower than its feature list. Concede SaaS glue to n8n, repo-event bots to gh-aw, one-off fan-outs to Claude Code, Python-native agent products to LangGraph or Temporal, and community and polish to Archon. Claim the ground where coding agents do repeated, item-by-item judgment work inside ops pipelines on your own infrastructure, and where that agent work should shrink over time. Three risks need public answers before launch: Anthropic's subscription-login policy for automated runs, the perception of a v0.1.0 project with one maintainer, and the fact that codify's replay oracle only covers branches it has already seen.

A note on evidence: the research checked competitors against primary docs, source and APIs, but Markov's own capabilities came from its project brief and were not independently re-verified. Every "Markov wins" statement below should be read as "if the brief is accurate".

## Agent-plus-deterministic workflows became table stakes in 2026

The research found the coding-agent orchestration market split into four groups. First-party vendors are adding orchestration: Claude Code, Codex, Copilot, Cursor, Devin, Warp. Open-source engines wrap agent CLIs: Archon, Microsoft Conductor, Goose, claw-orchestrator, Omnigent. Parallel-session GUIs run interactive sessions side by side: Vibe Kanban, Claude Squad. Swarm projects such as ruflo take the opposite approach and let the agents coordinate. Markov sits in the second group, and that group already has a well-adopted leader. Archon calls itself "the first open-source harness builder for AI coding. Make AI coding deterministic and repeatable", and its workflows mix agent prompt nodes, bash and script nodes, loops, approval waits and child workflows ([GitHub API](https://api.github.com/repos/coleam00/Archon), [Archon README](https://github.com/coleam00/Archon)). Its guiding rule, "YAML coordinates, code computes, agents judge", is close to Markov's own thesis that workflows queue, count and track state while agents make one judgment per item ([why-archon](https://archon.diy/getting-started/why-archon/)).

The idea also went mainstream in the frameworks. Google ADK 2.0 nodes can be "deterministic Python functions" next to LLM agents and human checkpoints ([adk.dev/2.0](https://adk.dev/2.0/)). Microsoft Agent Framework 1.0 shipped in April 2026 with graph workflows and YAML declarative agents ([DevelopersDigest](https://www.developersdigest.tech/blog/microsoft-agent-framework-whats-new-2026)). Industry voices push the same split. UiPath's CEO argues that a script costs nothing to run while an agent spends tokens on every run ([diginomica](https://diginomica.com/uipath-says-deterministic-automation-cant-be-replaced-ai-agents-q1-fy2027-numbers-support-case)). HumanLayer's 12-factor agents describe good agents as "mostly deterministic code, with LLM steps sprinkled in" ([12-factor agents](https://github.com/humanlayer/12-factor-agents)). Microsoft's Copilot Studio added a deterministic "Workflows" designer behind agent front ends ([candede](https://www.candede.com/articles/evolution-copilot-studio-workflow-designer)). The thesis is consensus now, and Markov cannot own it.

Single-call agent automation is also solved by the vendors themselves. `claude -p` ships `--json-schema`, `--max-turns`, `--max-budget-usd`, session resume and stream-json events ([headless docs](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-reference)). `codex exec` ships `--json`, `--output-schema` and `codex exec resume`, though it documents **no turn, token, time or budget caps** ([Codex non-interactive docs](https://learn.chatgpt.com/docs/non-interactive-mode)). Scheduling is commoditized too. Claude Code scheduled tasks run on cron, API and GitHub triggers on Anthropic's cloud or a self-hosted environment ([routines docs](https://code.claude.com/docs/en/routines)). Cursor Automations fire on schedules and on Slack, Linear, Sentry and PagerDuty events ([Cursor forum](https://forum.cursor.com/t/introducing-cursor-automations/153733)). Warp Oz runs cron-scheduled cloud agents ([Warp docs](https://docs.warp.dev/platform/triggers/scheduled-agents/)). Durability has commoditized at the SDK layer as well: Dapr Agents 1.0, Vercel WorkflowAgent, DBOS and Temporal integrations all make agent loops resumable ([Diagrid](https://www.diagrid.io/blog/dapr-agents-1-0-durable-cloud-native-production-ready), [Vercel AI SDK 7](https://vercel.com/blog/ai-sdk-7), [Pydantic durable execution](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/)).

That leaves a clear list of claims Markov should **stop leading with**. Five are no longer differentiated: "YAML workflows mixing agents and deterministic steps" (Archon, Conductor and gh-aw `steps:` all do it), "headless agent with JSON-schema answers" (built into both CLIs), "durable resume" (Archon, LangGraph and every durable engine), "scheduled agents" (every vendor), and "vendor neutral" (shared with gh-aw, Archon, Conductor, Omnigent and Vercel's harness). Two more claims are only partly differentiated: live transcripts (Archon, Conductor and gh-aw all have them) and human gates (Archon, Conductor, Windmill and Kestra have them).

### Archon is the hardest question

Archon matches Markov's shape almost node for node: `depends_on`, `when:`, loops ending on `until_bash` or a validated field, structured `output_format` enforced on Claude and Codex, sub-workflows, durable waits and explicit resume ([workflow language](https://archon.diy/reference/workflow-language/)). It has things Markov lacks. It has **75 contributors and minor releases every one to four weeks** ([releases API](https://api.github.com/repos/coleam00/Archon/releases)). It has chat adapters (Slack, Telegram, Discord, GitHub, GitLab, Gitea) and native schedules and webhooks ([triggers](https://archon.diy/guides/workflow-triggers/)), plus a worktree per run, Pi support and a bundled SDLC workflow pack. Its weak points are real, though. There are no turn or token caps on agent nodes. The USD cap is Claude-only. The run budget "refuses" the next attempt rather than killing a running one, and "spend can exceed `max_spend_usd`" ([run budgets](https://archon.diy/reference/workflow-language/#run-budgets)). AI nodes have only an idle timeout. There are no HTTP, k8s or ansible node types. Fan-out works only on child workflows. Archon deliberately refuses `set_fact`-style computation, and it explicitly declines to maintain Kubernetes deployment. It sends telemetry by default ([README](https://github.com/coleam00/Archon/blob/dev/README.md)) and needs AVX2 on x64. **Honest answer:** "If you want an issue-to-PR software factory with chat integrations today, use Archon. Markov is for when you need hard kill limits on every agent step for both vendors, ops-native steps, k8s-hosted runs, a step debugger, and a way to shrink agent spend over time with codify."

### Claude Code dynamic workflows win on time-to-value

Claude writes the orchestration script from one sentence. Fan-out agents share prompt cache, schema outputs get five validation attempts, runs pause and auto-resume at usage limits, and a run scales to **1,000 agents** ([workflows](https://code.claude.com/docs/en/workflows)). For one-off audits and migrations, nothing in YAML will beat that. The structural limits are documented in Anthropic's own words. There is "No direct filesystem or shell access from the workflow itself", "No mid-run user input", and the "Large workflow" warning "is advisory: it doesn't pause or limit the run". Resume works only "in the same session", and a mid-fan-out failure reruns agents that had already finished ([workflows](https://code.claude.com/docs/en/workflows)). Every deterministic action therefore costs an agent call. That is the exact cost that codify exists to remove. Anthropic also uses the word "codified" for orchestration ("A workflow moves the plan into code"), so Markov's messaging must separate *codifying the orchestration* from *codifying the work inside agent steps*. **Honest answer:** "For a one-off job in one repo, use dynamic workflows. When the same pipeline runs nightly over hundreds of items, Markov's zero-token native steps, hard budgets, cross-process resume, human gates and Codex support start to pay off."

### Claude Code scheduled tasks are vendor-hosted cron for one agent

Scheduled tasks run a saved prompt against repos and connectors on Anthropic cloud or an org's self-hosted environment, triggered by schedule, API or GitHub event ([routines](https://code.claude.com/docs/en/routines)). The constraints are notable. Cron "more often than once per hour" is rejected. There are hourly caps of 100 scheduled runs per account and 30 API fires per task. Runs draw on subscription usage. Run status reports "how the session ended, not whether Claude completed the work" ([routines](https://code.claude.com/docs/en/routines)). **Honest answer:** "For a Claude-only, single-prompt job that runs hourly or less often, use scheduled tasks. Markov is for multi-step pipelines with deterministic steps and gates that decide success, mixed vendors, and your own cluster and secrets."

### gh-aw owns repo-event automation

GitHub Agentic Workflows compile Markdown into Actions. They have the most mature security model in the category: read-only agents, sanitized and threat-scanned "safe outputs", a network firewall, and SHA-pinned dependencies. They also enforce budgets by default: `max-turns`, `max-ai-credits` (1,000 per run) and `max-daily-ai-credits` ([gh-aw site](https://github.github.com/gh-aw/), [frontmatter](https://github.com/github/gh-aw/blob/main/docs/src/content/docs/reference/frontmatter.md)). v1.0.1 shipped on 27 October 2026, although the site still calls it a technical preview ([release](https://api.github.com/repos/github/gh-aw/releases/latest)). Its shape is one agent job per workflow, it is tied to GitHub events and runners, and the agentic step defaults to a 20-minute timeout. **Honest answer:** "Concede PR bots and issue triage to gh-aw. Markov targets work that isn't a GitHub event: k8s, Ansible and HTTP-API pipelines, long per-item loops with resume, local debugging, and codify."

### Windmill, Conductor, Vercel and Kestra each win in their own category

**Windmill** is a mature general platform (Rust, Postgres, Helm, 20+ languages, nsjail and OCI sandboxing) with an AI Sandbox that runs Claude Code from a template. That template uses `permissionMode: "bypassPermissions"`, logs tokens without enforcing anything, and gives Codex only an unescaped `execSync` skeleton ([AI sandbox](https://www.windmill.dev/docs/core_concepts/ai_sandbox)). Restart-from-step, concurrency limits and approval forms are Enterprise features, and the prebuilt CE images contain proprietary code ([LICENSE](https://raw.githubusercontent.com/windmill-labs/windmill/main/LICENSE)). Honest answer: "If you already run Windmill, add a Claude Code step. If coding agents are the core of the work, Markov's enforced budgets, schema answers for both CLIs, free resume, single binary with no Postgres, and Apache-2.0 matter."

**Microsoft Conductor** has the schema closest to Markov's: YAML, Jinja2 routes, `for_each` with `key_by`, and script, set and human_gate steps. It adds Copilot-seat economics, local models, a live DAG dashboard and OpenTelemetry ([README](https://github.com/microsoft/conductor)). But its budget runs in audit mode by default and "starts a fresh budget window" on resume, its Claude Agent SDK path is experimental, it has no Codex support, and its SUPPORT.md is still the unedited template ([workflow syntax](https://github.com/microsoft/conductor/blob/main/docs/workflow-syntax.md), [SUPPORT.md](https://github.com/microsoft/conductor/blob/main/SUPPORT.md)). Honest answer: "Pick Conductor if your org pays for Copilot and wants Microsoft-namespace tooling. Pick Markov for enforced budgets that survive resume, Codex, and ops steps."

**Vercel AI SDK harnesses** give one typed interface over about 11 agent runtimes, but the docs say "Harness packages are **experimental**. Expect breaking changes", with about 176 patch releases in five months. The Claude Code and Codex adapters need a network sandbox with an exposed port, in practice Vercel Sandbox ([claude-code harness](https://ai-sdk.dev/providers/ai-sdk-harnesses/claude-code), [npm](https://registry.npmjs.org/@ai-sdk/harness)). Honest answer: "If you are embedding a coding agent in a TypeScript product, use Vercel. Markov is for running ops pipelines, not building apps."

**Kestra** is declarative YAML like Markov. It is Apache-2.0, has 30k stars, a $25M Series A, and reports 30,000+ organizations. Kestra 1.0 added AI agent tasks, MCP and human-in-the-loop ([Kestra 1.0](https://kestra.io/blogs/release-1-0), [IT Brief](https://itbrief.com.au/story/kestra-raises-usd-25-million-to-expand-workflow-platform)). Its agents are API-LLM tool loops, not CLI coding agents in a repo. Kestra's own launch post calls agents "unsuitable for mission-critical tasks requiring strict control and repeatability", which supports Markov's codify thesis. Honest answer: "Kestra wins for general data and ops orchestration with LLM calls. Markov wins when the step is a coding agent that needs caps, transcripts and eventual codification."

### Plain scripts and GitHub Actions are the most common objection

On comparable Show HN threads, the most common first comment is some version of "why not a shell script / Makefile?" ([HN 46549444](https://news.ycombinator.com/item?id=46549444)). One commenter says "You could accomplish _all_ of it with claude -p" ([HN 47434024](https://news.ycombinator.com/item?id=47434024)). That is true for short linear flows. Pain shows up as the workflow grows: "bash scripts start clean but the sprawl kicks in quick", and nobody in the thread settled how to fan out and merge with headless mode alone ([HN 47434024](https://news.ycombinator.com/item?id=47434024)). The vendor docs leave several jobs to the caller. The caller must check that `structured_output` is present, parse failures printed to stdout despite a zero exit code, "leave headroom" because spend can pass the budget cap, and pin `--bare`, since without it `-p` runs project hooks and MCP servers "even in a folder you've never trusted" ([headless docs](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-reference)). GitHub Actions adds 6-hour jobs, a 256-job matrix and cheap minutes. But schedules run only from the default branch, public-repo schedules turn off after 60 days of inactivity, and `act` only approximates real runs locally ([Actions limits](https://docs.github.com/en/actions/reference/limits), [Claude Code GH Actions docs](https://code.claude.com/docs/en/github-actions)). **Honest answer:** "Under about three linear calls, use a script. Beyond that you end up rebuilding checkpointing, bounded fan-out, per-item cost, schema checks, secret masking and a transcript viewer. Markov is that script with the hard parts done, and it runs fine as one step inside an Actions job."

## Codify is new as a mechanism, not as an idea

`markov codify` is the clearest differentiator in every category the research covered. It needs careful framing, because the *idea* has heavy prior art. In browser automation, Skyvern records successful runs as Playwright code and reports **2.7× cheaper, 2.3× faster** replays, vendor-reported ([Skyvern](https://www.skyvern.com/blog/asking-ai-to-build-scrapers-should-be-easy-right/)). Stagehand caches resolved actions and falls back to the LLM on a miss ([Stagehand](https://docs.stagehand.dev/v3/best-practices/caching)). Browser Use's workflow-use records interactions as deterministic workflows. Research systems compile agent behavior into workflows. TraceCompiler found a **median 51.4% of agent calls removable** across 56 scenarios, and it classifies "residual LLM decisions" much as Markov separates judgments ([arXiv 2608.02680](https://arxiv.org/html/2608.02680v1)). Compiled AI reports token break-even at about **17 transactions** and about 57× fewer tokens at 1,000 ([arXiv 2604.05150](https://arxiv.org/abs/2604.05150)). Agentic Plan Caching (NeurIPS 2025) cut cost **50.31%** at 96.61% of optimal accuracy ([arXiv 2506.14852](https://arxiv.org/abs/2506.14852v1)). Practitioners already circulate the thesis as a prompt: an `agent-skills` PR tells agents to convert agentic workflows into deterministic ones ([GitHub PR](https://github.com/akash2991/agent-skills/pull/21)). Even Archon notes that "a deterministic producer owns the same contract", so its users can codify by hand ([archon.diy](https://archon.diy/reference/workflow-language/)).

What appears new is the combination. No one combines all five of these parts. First, an **incremental loop** that moves one job per iteration, with versioned promotion and a per-iteration cost ledger; everything else is one-shot or cache-on-success. Second, an **offline HTTP record/replay oracle** used to *gate a refactor*. vcrpy, Keploy and the AI cassette tools use replay for regression tests ([TraceOps](https://pypi.org/project/TraceOps/)), and Temporal uses it to check workflow-code determinism ([Bitovi](https://bitovi.com/blog/replay-testing-to-avoid-non-determinism-in-temporal-workflows)), but neither uses it to approve a refactor. Third, **two equivalence modes**: strict (same outputs, with an LLM judge for prose) and loose (same actions on the same items). Fourth, a **second refactor type** that splits a broad agent step into focused per-item calls with schema answers. That automates 12-factor's "small, focused agents", and the research found no system doing it. Fifth, it is **domain-general** across shell, HTTP, k8s and ansible rather than limited to the browser DOM. The notes suggest a positioning line: *Skyvern and Stagehand cache what the agent clicked; TraceCompiler mines many traces into a workflow; Markov refactors your workflow one validated step at a time until the agent only makes judgments.* Claims of uniqueness should be phrased as "we found no equivalent", because absence in search is not proof. UiPath (coding agents authoring `.flow` files) and n8n (AI Workflow Builder plus evaluations) are each a step away from "rewrite this agent step as nodes".

The other claims that survive are less dramatic but concrete. **Kill-on-breach limits applied the same way to both CLIs** fill a real gap: Codex documents no caps, Archon's USD cap is Claude-only, Conductor audits by default, and Claude Code workflows only warn. **Native infra steps** (k8s_job, ansible, paginated HTTP with SSE, OpenShell sandboxes) and **rule-engine gates with salience and forward chaining** appeared in no competitor's primary docs. Agent frameworks evaluated in the research showed no comparable **step debugger with breakpoints**. The same research note names LangGraph Studio as the closest but did not verify its 2026 state, so this comparison is mainly against the agent-framework category. Finally, a **Go single binary under Apache-2.0** with no Postgres, Bun or AVX2 requirement and no default telemetry is a modest but real contrast with Archon, Windmill and n8n.

## Three risks need public answers before launch

**Subscription login is the question users will ask unprompted.** Anthropic's legal page says OAuth sign-in supports "ordinary use of Claude Code and other native Anthropic applications". It says developers "building products or services… including those using the Agent SDK, should use API key authentication", and that "Advertised usage limits… assume ordinary, individual usage". It also says plainly that the policy does not "prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription", and that Anthropic "may [enforce] without prior notice" ([legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). Markov drives the unmodified CLI with the user's own login and does not handle credentials, so it appears to fall inside the permitted case. That is the research's reading, not legal advice. There are two grey zones. Heavy cron and fan-out on a subscription may not count as "ordinary, individual usage". And a hosted or shared markovd that pools one login would become "intermediating". Third-party OAuth clients were blocked during a January–February 2026 enforcement wave, and at least one developer reported a ban ([WinBuzzer](https://winbuzzer.com/2026/02/19/anthropic-bans-claude-subscription-oauth-in-third-party-apps-xcxwbn/)). The October 2026 support update gives a clean path: Max, Ultra and Team plans now include monthly API credits usable by `claude -p` *with an API key* ([Claude support](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). OpenAI is more permissive. It recommends API keys for automation but documents access tokens for "trusted scripts, schedulers, and private CI runners" ([Codex auth](https://learn.chatgpt.com/docs/auth)). Markov should publish an "Is this allowed?" FAQ before launch. It should recommend API keys (or plan API credits) for scheduled and markovd runs, never store or proxy OAuth tokens, and link both vendors' pages.

**Single-maintainer v0.1.0 perception is the second risk.** Comparable launches draw "Is there a new agent orchestrater posted every day?" and "Day seven: Never open this repo again" ([HN 47160980](https://news.ycombinator.com/item?id=47160980)). Archon has 75 contributors and weekly releases, but even it is concentrated on two committers ([contributors API](https://api.github.com/repos/coleam00/Archon/contributors)). Openness helps here. Statewright's patent and FSL license drew "makes me want to run away" ([HN 48108778](https://news.ycombinator.com/item?id=48108778)). Markov's Apache-2.0 license, plain YAML and use of the standard CLIs mean little lock-in. A user who leaves still has readable workflows and the same `claude -p` calls. Visible cadence, a public roadmap and a stated maintenance commitment matter more than features at this stage.

**Codify's replay oracle only proves what it has seen, which is the third risk.** A candidate is validated against the HTTP exchanges and items from recorded runs. A codified filter can pass replay and still misclassify an unseen item. TraceCompiler hit exactly this when "the required branch was never observed" ([arXiv 2608.02680](https://arxiv.org/html/2608.02680v1)). If the candidate issues requests the original didn't (different pagination, order or parameters), replay has no response and rejects it. That can be a useful strictness signal or a false rejection. The strict mode's LLM judge and the loose mode's "valid value" checks can let regressions of meaning through, the same semantic-drift problem the cassette tools had to add thresholds for ([cendor-cassette](https://pypi.org/project/cendor-cassette/)). Unlike Skyvern and Stagehand, Markov (per its brief) has no automatic fall-back-to-agent when a promoted native step fails in production. No independent study yet measures reliability before and after this kind of migration. Markov should document these limits and offer clear mitigations: record several runs, perturb recorded responses, and add a production fallback or alarm. It should also publish its own measured break-even (codify cost against per-run savings) rather than borrowing others' numbers.

Smaller risks round this out. The YAML objection is real: "I see 'prompt scripting' as strictly worse than code" ([HN 46549444](https://news.ycombinator.com/item?id=46549444)), and CI YAML tends to rot into a bad programming language ([engineered.at](https://engineered.at/articles/notes-an-ice-cold-take-on-ci-config-systems)). For some users a k8s requirement is "a non-starter" ([HN 47520220](https://news.ycombinator.com/item?id=47520220)). First-party vendors improve monthly, and Claude Code workflows could gain shell steps or hard budgets at any time. Finally, every Markov claim in this report should be re-verified against the shipping binary before it appears in marketing.

## Lead with codify and a measured story, not "workflow engine"

The positioning that survives scrutiny is narrow: **Markov is the agent-aware runtime for repeated, item-level coding-agent work inside ops pipelines on your own infrastructure, and it shrinks the agent's share of that work over time.** It is not a CI system, not a SaaS glue tool and not an agent framework. It should say so and offer to run *inside* those systems: as a GitHub Actions step, a Jenkins or Rundeck job, or a CronJob replaced by markovd. Four recommendations follow from the evidence.

First, lead the launch with one concrete, measurable story rather than a category claim. On HN, spectacle and crisp theses won (Claude Code Godot games 337 points, Statewright 126), while generic orchestrators stalled (OpenSwarm 34, Zenflow 33) ([HN Algolia](https://hn.algolia.com/api/v1/search?query=Show%20HN%20claude%20code%20orchestrat&tags=story&numericFilters=created_at_i%3E1735689600,points%3E30&hitsPerPage=25)). Something like "nightly triage of N items; codify cut agent tokens by X% with identical replayed output over K iterations" uses the break-even framing the research literature already made credible. Pair it with Statewright-style thesis language, since "the state engine is the part that can't hallucinate" resonated. Developers in 2026 trust AI output when they can "verify it easily" ([IT Brief](https://itbrief.co.uk/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)). JSON-schema answers, rule gates and replay are exactly that, and should be pitched as verification rather than features.

Second, put the honest "why not X" answers in the README before anyone asks: a script under three calls, gh-aw for repo events, Claude Code workflows for one-offs, n8n for SaaS glue, Temporal or LangGraph for Python products, and Archon for an issue-to-PR factory with chat integrations. Conceding up front reads as confidence and pre-empts the top comment. Third, answer the dominant technical questions in the docs: sandboxing and secrets (the most frequent question on Optio's thread), subscription versus API-key auth, "where must a human be?" (breakpoints and prompt gates), and the codify coverage limits above. Show that conditionals and loops do not turn YAML into a programming language, and that logic lives in script steps. Fourth, sequence the surface area. Lead with local-first `markov run` and codify. Present markovd and Kubernetes second, as the path to scheduled production, so the k8s requirement never becomes the first impression.

## Conclusion

The research changes what Markov is competing on. A year ago, chaining headless coding agents with deterministic steps under a YAML file would have been the pitch. By November 2026 that is the shared baseline of Archon, gh-aw, Conductor and every major framework, and first-party vendors ship scheduling and fan-out for free. What remains scarce is a *direction of travel*: tooling that treats agent spend as debt to be paid down with evidence, rather than a constant to be scheduled. Codify is the only feature found anywhere that makes a workflow cheaper and more deterministic each time it is run and examined. The industry's own voices supply its argument, from UiPath's CEO on tokens per run to Kestra's admission that agents are unsuitable where repeatability matters.

That also defines Markov's exposure. Its moat is a mechanism that is unproven at v0.1.0, sits one step from UiPath's and n8n's roadmaps, and carries a known blind spot for unseen branches. The project should spend its launch credibility on proving codify with public, reproducible numbers and on documenting where codify fails. The research suggests that one convincing before-and-after case will earn more first users than any feature table, and that conceding most of the field openly will help Markov hold the part it actually leads.

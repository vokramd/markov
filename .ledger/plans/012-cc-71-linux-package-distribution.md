Alternative: `~/markovd-repos` outside document root with a managed symlink, but this requires confirming Apache link support and adversarial rsync traversal tests; changing/replacing the link from a site-writable root undermines the boundary. Apache `Alias` normally needs server/vhost configuration, not `.htaccess`; do not assume DreamHost exposes it. A separate DreamHost login for markovd.com, set up by the human in the panel, gives stronger account isolation from tannerjc.net and is an optional improvement. Do not silently accept whole-docroot site-key write access if routing isolation is unavailable; report for human risk acceptance or a revised layout.
